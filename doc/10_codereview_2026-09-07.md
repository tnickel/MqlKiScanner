```

         ──> mql5/browser_session.py (Selenium-Chrome: Login, CSV-Fallback)

                    |
                    v

                    |
                    v

                ──> forensics/{martingale, exposure, stops, drawdown, baskets, news}
                ──> stats.compute
                ──> scoring.evaluate (7 Dimensionen, Gewichte, harte DD-Schranke, forensics_complete-Gate)
                    |
                    v
 db.py (SQLite: signals, trade_files [Snapshot+SHA-256], forensik, analyses)
                    |
                    v
 llm/client.py (GLM via Z.ai, 2 Stufen: Flash=risiko_analyse, stark=trade/gesamt/portfolio)
     Payloads NUR aus Engine-JSON: pipeline._kandidat_json/_forensik_json + trade_data.build_trade_payload
                    |
                    v

```

Zentrale Ordnungsprinzipien (aus AGENTS.md, im Code durchgesetzt):

1. Code rechnet ALLE Zahlen; das LLM bekommt fertige JSONs (Design-Regel 1).
2. Kein Kandidat erhält positives Urteil vor bestandener Pflicht-Tests (Regel 2) — siehe F1.
3. "Kein Stop-Nachweis" ist Warnflag, nie Entlastung (Regel 2, stops.py-Modulkopf).
4. FORENSICS_VERSION (analysis_version.py, aktuell 2) erklärt ältere Befunde
   für veraltet (pipeline.results_from_db).

### F1 — MITTEL: Ampel „🟢 Kandidat" ist nicht an den Stop-Nachweis gekoppelt

- Ort: `src/mqlkiscanner/pipeline.py:229-235` (`ampel_for`), ursächlich
  `src/mqlkiscanner/scoring.py:94-100` (Struktur-Dimension).
- Behauptung: Ein Signal OHNE jeden Stop-Loss-Nachweis (kein Orderbuch, kein
  Cluster) kann die Ampel 🟢 „Kandidat" erhalten, solange Score < 5 und
  Ertrag ≥ Schwelle sind. Die fehlende Absicherung schlägt nur mit +2,0 auf
  EINE von sieben Dimensionen durch (Struktur: Basis 3,0 − 1,0 nicht möglich
  da nicht bewiesen, +2,0 für "kein Beweis" = 5,0) und kann durch harmlose
  andere Dimensionen kompensiert werden.
- Rechenweg: dims = {drawdown 1,0 · structure 5,0 · margin 1,0 · copy 3,0 ·
  track 2,5 · transparency 5,0 · broker 5,0}
  score = 0,25·1 + 0,25·5 + 0,15·1 + 0,15·3 + 0,10·2,5 + 0,05·5 + 0,05·5
        = 2,85 < 5.
- Nachweis (ausgeführt, Ausgabe wörtlich):

  ```
  $ cd src && python - <<'EOF'
  from mqlkiscanner.pipeline import ScanResult, ampel_for
  r = ScanResult(id=999999, name="SYNTH-Test", source_kind="live",
      forensik_vorhanden=True,
      stop_nachweis="Verlustdistanzen ungebundelt, laufen frei (kein Stop-Nachweis)",
      score=2.85, ertrag_monat_pct=6.0, martingale_flag=False,
      schranke_verletzt=False)
  print(ampel_for(r, {"schranke_eq_dd_pct": 30.0, "min_ertrag_pct_monat": 5.0}))
  EOF
  -> ('🟢', 'Kandidat: Forensik bestanden, Score < 5, Ertrag ok')
  ```

- Einordnung: Das Projekt kennt das Problem teilweise — der Gesamtbericht-
  Prompt (`llm/prompts.py`, DEFAULT_GESAMTBERICHT: „ohne Stop-Nachweis keine
  Empfehlung") und der Portfolio-Prompt verbieten die Empfehlung, und
  `help_content.py` („risk_status") weist den Nutzer an, den Stop-Nachweis
  separat zu prüfen. Die AGENTS.md-Kernfrage („Ist der Schutz bewiesen oder
  nur behauptet?") wird damit aber nur textlich/LLM-seitig beantwortet, nicht
  von der Engine-Ampel. Wer nur die Tabelle liest, sieht Grün.
- Vorschlag: In `ampel_for` das Grün-Gate um die Bedingung erweitern, dass
  `stops.stop_evidence in ("direct", "cluster")` gilt (Feld muss dafür von
  pipeline in ScanResult mitgeführt werden; `stop_nachweis` ist nur Text).
  Alternativ das Label „Kandidat" in „Vorprüfung bestanden" umbenennen.
- Schwere: MITTEL (fachliche Kernregel, keine technische Fehlfunktion).

### F7 — BEOBACHTUNG: `eq_dd_caveat` ist live nicht setzbar (Kalibrierung vs. Lauf)

- Ort: `src/mqlkiscanner/scoring.py:79` (Ausnahme greift nur, wenn gesetzt),

  Signal wird ohne manuellen Eingriff dauerhaft rot.
- Vorschlag (optional): Feld `eq_dd_caveat` je Signal in

### F11 — HINWEIS: SQLite-Fremdschlüssel sind nicht erzwungen

## 5. Sicherheitsreview

Geprüft und in Ordnung:

1. Geheimnisfreiheit im Repo: `git ls-files` zeigt keine Datei mit
   Secrets (siehe Abschnitt 2). `.gitignore` deckt `.env`, `**/secrets.local.json`,
   `data/mql5_cookies.json`, `data/chrome_profile/`, `data/*.db*`,
   `data/runs/`, `data/trades/` vollständig ab. Die lokal existierenden
   `config/secrets.local.json`, `data/mql5_cookies.json` und `.env` sind
   nachweislich ungetrackt.
2. Ablagekette: `secrets_store.get_secret` — Umgebung > `.env` >
   `secrets.local.json`; `secret_status()` liefert nur Booleans;
   `save_secrets` macht `chmod 0600` (best effort, Windows-Kommentar stimmt).
3. Kein Credential-Reach in LLM-Kontext: `_kandidat_json`/`_forensik_json`/
   `build_trade_payload` enthalten keine Zugangsdaten; MQL5-Credentials
   werden ausschließlich in `mql5/*` gelesen (AGENTS.md Regel 5 eingehalten).
4. Cookies: Klartext-JSON lokal (gitignored, chmod best effort). Als
   Restrisiko dokumentiert (browser_session.py-Modulkopf, admin.py-Hinweis
   „nicht verschlüsselt", SECURITY.md). Für ein Lokaltool akzeptabel.
5. SQL: ausschließlich parametrisierte Statements (`?`) in db.py — keine
   String-Interpolation von Nutzereingaben. UI-Eingaben (Zahlen/Selects)
   fließen nur als Werte.
6. Pfad-/Dateihandling: atomare Writes mit `tempfile` + `fsync` +
   `os.replace` (pipeline.save_run, exporter.publish_validated_export,
   db._snapshot_trade_file); Trade-Snapshots werden nach SHA-256-Inhalt
   versioniert, ein Transaktions-Rollback kann alten Stand nicht
   überschreiben (dafür gibt es einen eigenen Test:
   `tests/test_second_review_storage.py::test_cache_refresh_and_sql_rollback_keep_old_snapshot_and_finding`).
7. ToS/Accountschutz: RateLimiter (Mindestabstand 2 s + Jitter + Extra-
   pausen), Backoff 429/503 verdoppelt, HTTP 403 => sofortiger Hard-Stop,
   Fail-Fast nach 3 systemischen Fehlern (`mql5_fail_fast_after`), 24-h-CSV-
   Cache. AGENTS.md-Vorgabe „behutsam scrapen" ist implementiert.
   Einordnung: `--disable-blink-features=AutomationControlled` (browser_session.py:112)
   ist Anti-Detection-Automation; Einsatz für den Login am eigenen Account
   und im Kontext der dokumentierten Analyse-Nutzung vertretbar, bleibt aber
   eine Grauzone gegenüber MQL5-ToS — vom Projekt selbst so dokumentiert
   (AGENTS.md Technik 6, SECURITY.md).
8. Streamlit-Konfiguration: `headless = true`, keine `server.address`/
   `enableCORS`-Öffnungen; App ist für lokale Nutzung gebaut.

Keine Safety-Actions offengelegt; keine Schwachstelle mit Fernwirkung
gefunden (Angriffsfläche = lokale Dateien + MQL5-Login des Nutzers).

## 6. Abgleich mit AGENTS.md (feste Regeln)

| Regel | Status | Nachweis |
|---|---|---|
| Risiko VOR Ertrag; harte DD-Schranke 30 % | ERFÜLLT | scoring.evaluate: `barrier_dd > schranke` → `schranke_eq_dd_verletzt`; UI erzwingt 0 < DD ≤ 30 und Ertrag ≥ 5 (admin.py:293-307); Ampel 🔴 bei Verstoß (pipeline.py:224-226) |
| Ertrag > 5 %/Monat | ERFÜLLT (≥, nicht >) | Ampel prüft `>= min_ertrag_pct_monat` (pipeline.py:231); admin.py dokumentiert „≥ eingestellter Schwelle" ehrlich. Hinweis: AGENTS.md sagt „über 5 %" — exakt 5,0 zählt als ok. Randfall, offen dokumentiert. |
| Kernfrage Stop bewiesen/behauptet | TEILWEISE | Engine liefert Evidenzstufen (stops.py) und scoring bestraft fehlenden Nachweis; aber Grün nicht an Nachweis gekoppelt → F1 |
| Design 1: LLM rechnet nie | ERFÜLLT | Alle Zahlen aus Engine-JSONs (pipeline._forensik_json, trade_data.build_trade_payload); Prompts verbieten eigene Berechnungen; LLM-Antworten werden nie als Zahl zurückverwendet |
| Design 2: kein Positivurteil vor Pflicht-Tests | TEILWEISE | `forensics_complete`-Gate existiert und blockt Score/Urteil; „Pflicht-Tests bestanden" heißt aber nur „Tests durchgelaufen", nicht „Stop-Nachweis erbracht" → F1 |

## 8. Positive Befunde (explicit verifiziert)

P1 — Kalibrierung reproduzierbar: verify_engine 85/85 PASS, inkl. der vier
